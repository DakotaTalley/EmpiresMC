# EmpiresMC 1.0 Release

Phased plan for the 1.0 release of EmpiresMC — a Fabric mod (Kotlin) where the world does not belong to the player: every chunk they want to mine or build in must first be claimed with an upgradeable Scepter. Land itself is the progression system.

Each phase has its own document with design decisions, a tracking checklist, flagged risks, and exit criteria. Phases are ordered so the mod is runnable and testable at the end of every phase.

| Phase | Scope |
|---|---|
| [1 — Project scaffolding](1.0-release/phase-1-project-scaffolding.md) | Gradle/Loom/Kotlin project, `fabric.mod.json`, LGPL license, test wiring, CI; empty mod loads in dev. |
| [2 — Claim data & persistence](1.0-release/phase-2-claim-data-and-persistence.md) | Claim registry and player empire state, world saved data, allowance math, unit tests. |
| [3 — The Scepter](1.0-release/phase-3-the-scepter.md) | Claim item as a stateless handle: first-join grant, loss protection, recovery paths. |
| [4 — Claiming & unclaiming](1.0-release/phase-4-claiming-and-unclaiming.md) | Scepter use-gestures, starting claim, unclaim cooldown, feedback messages. |
| [5 — Protection enforcement](1.0-release/phase-5-protection-enforcement.md) | Server-side break/place/modify restrictions outside claims, explosion policy, gametests. |
| [6 — Claim visualization](1.0-release/phase-6-claim-visualization.md) | Client sync payloads and in-world claim border rendering while holding the Scepter. |
| [7 — Configuration](1.0-release/phase-7-configuration.md) | JSON config file, validation, reload command, migration of hardcoded constants. |
| [8 — Scepter upgrades](1.0-release/phase-8-scepter-upgrades.md) | Config-driven tier table (resources + XP), upgrade interaction, chunk grants. |
| [9 — Commands & polish](1.0-release/phase-9-commands-and-polish.md) | Player/admin commands, localization, sounds, advancements, real Scepter art. |
| [10 — Exploit hardening & balance](1.0-release/phase-10-exploit-hardening-and-balance.md) | Work the exploit register, balance the progression curve, performance and save-integrity passes. |
| [11 — Release](1.0-release/phase-11-release.md) | Docs, release CI, Modrinth/CurseForge publishing, final QA. |

**Adding features mid-development:** new work gets its own phase file (`1.0-release/phase-N-<name>.md`) plus one row here — this summary never grows beyond the phase list. Ideas that aren't scheduled yet go to the [backlog](1.0-release/backlog.md).
